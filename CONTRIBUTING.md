# Contributor’s Guide

This guide is intended for anyone considering opening an **issue** or **pull request**. If in doubt,
please open a [discussion](https://github.com/laschuet/PrototypesCriticisms.jl/discussions); we can
always convert that to an issue later.

## Quick guide

**I have a question!**

Open a discussion.

**I have an idea for a feature!**

Open a discussion.

**I have a bug!**

1. Search the issue tracker and discussions for similar issues.
2. If you don't have steps to reproduce, open a discussion.
3. If you have steps to reproduce, open an issue.

**I'd like to contribute!**

Pick an issue and start working on it. If you need help or guidance, feel free to comment on the
issue.

**I've implemented a feature!**

1. If there is an issue for the feature, open a pull request.
2. If there is no issue, open a discussion and link to your branch.

## General guidelines

### Issues should be actionable

The [issue tracker](https://github.com/laschuet/PrototypesCriticisms.jl/issues) is exclusively for
**actionable items**.

The issue tracker is **not** for discussions or feature requests. For those, we use GitHub
[discussions](https://github.com/laschuet/PrototypesCriticisms.jl/discussions). Once a discussion
leads to a clear, actionable items, it can be turned into an issue. This ensures that every issue is
ready for contributors to work on, making it easier to navigate and contribute.

#### When to open an issue or discussion

- **Question?** Start a discussion.
- **Feature idea?** Start a discussion.
- **Bug with clear reproduction steps?** Open an issue.
- **Uncertain if it’s a bug or unsure how to reproduce it?** Start a discussion.

### Pull requests should address an issue

Every pull request must be linked to an existing, approved issue.

Opening a pull request for something not previously discussed **may** result in it being closed or
left inactive indefinitely.

#### Working on features

Issues labeled as "feature" represent approved and well-defined feature requests. If your pull
request implements such an issue as described, it’s highly likely to be accepted.

> **Note:**
>
> Pull requests are **not** the place to discuss feature design. Avoid opening a work in progress pull request to discuss ideas. Instead, use discussions and share a link to your branch if needed.
